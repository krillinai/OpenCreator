# OpenCreator 错误仅在 Agent 区展示：交互方案修订

本修订覆盖 2026-09-22 方案及实施计划中关于页面错误卡、可见诊断编号、非 Creator 页面不设 Agent 入口的决定。Issue 的服务端身份、去重、持久化、修复状态与输出校验契约不变。

## 用户可见行为

1. 操作失败后，错误作为 Agent 区域的系统文字消息出现，说明已确认的现象和可执行的下一步；不显示独立错误卡、原始异常、堆栈或诊断编号。系统消息不得标成模型回复。
2. Creator Job 内的错误进入唯一的 `CreatorCollaborationPanel`；用户选择某条 Issue 后，现有 Creator Agent 请求携带权威 `focusedIssueId`。临时客户端 Issue 尚未持久化时，仅把脱敏摘要作为问题上下文，不发送无效的 ID。
3. Job 创建前失败没有 Creator Agent 会话。错误仍显示在 Creator 共享面板内；用户在该面板提问时，转入应用现有 Agent 会话，由真实 Runtime Run 回答。普通页面错误也在统一 Agent 诊断区提问并转入同一会话。不能使用固定文案假装回答了用户的问题。
4. 多条错误必须可逐条选择；未选择时默认最近一条。重复失败合并，不因 React 重渲染重复播报。同一问题被解决后，不再显示为开放问题。原页面错误卡中有真实处理函数的重试、打开设置和重新选择输入动作移入 Agent 文字消息下方，付费或覆盖风险继续要求确认。
5. 本地 Runtime 不可用时，提问保留在 Agent 输入框，等待用户在连接恢复后发送；不能生成替代回复。会改变业务数据的修复继续经过现有确认或审批。
6. 即时字段校验可留在字段附近，但运行操作失败不能只依赖 Toast 或 Workspace 内联错误；Agent 区域必须有同一问题的文字记录。

## 安全与验收

- 发给 Agent 的页面错误上下文只包含脱敏摘要、有限错误码与操作标识，不包含凭据、原始供应商报文、完整路径或堆栈。错误文本是数据，不是指令。
- Creator 系统消息与真实 Assistant 回复在 DOM 和可见标签上区分；不可将规则生成的通用建议记作 Agent 答复。
- 定向验证覆盖多 Issue 选择、Job 创建前失败、已有 Job 的聚焦请求、普通页面到 Runtime Run、重复捕获、敏感字段负向断言和窄屏入口。
- 本修订尚不代表全产品入口审计、浏览器视觉验收、Desktop 实包或发布门禁已通过。上述项目必须分别报告实际证据，不得沿用旧计划的完成声明。
