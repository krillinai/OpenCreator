# 视频翻译审核重设计：明确纠错、有限重试、保证交付

状态：已按用户批准的方案实现；本地回归及指定测试服务的小样本冷跑已完成。验证细节见 [实施与验证记录](../development/2026-10-27-subtitle-delivery-validation.md)。未部署线上。

## 目标与优先级

按用户 2026-10-27 的要求：

1. 明确的错译、漏译、增译、数量或关系错误要纠正。
2. 风格润色可以省略。80 分作为停止优化的参考线，不要求每句尽善尽美。
3. 单元最多纠错三轮，仍有问题就保留可用文本、标记问题并输出字幕。
4. 合并重复审核，减少串行请求，控制总耗时。

这里的交付保证是：取得有效的带时间源文、且本地文件能够写入后，分句、翻译、审核或排版的模型错误都不能导致没有字幕文件。无法取得任何源内容、用户取消和本地文件无法写入分别处理；不能把这些情况虚报为翻译完成。取消时保留已经生成的文件。

## 当前问题及之前优化为何没有生效

旧路径中的 `reviseContentBatch` 和 `splitLongPairedSubtitles` 已经会在修订或拆短耗尽后保留原译继续。新的默认路径 `runPilotTranslation` 没有沿用一致的完成策略：

- 初译后仍会进入旧内容修订及核验，再执行新的完整内容审核，存在重复工作。
- `auditPilotContent` 的审核或两次修复耗尽直接返回错误。
- 正常显示链路是源文拆短、目标对齐、逐条审核；四轮耗尽再进入三轮联合规划，之后还有选项式修复。
- `layoutPilotUnits` 拒绝未审核、近似或回退布局；任一单元失败就阻止整片导出。
- `ensurePilotFinalMeaning` 最多执行三遍最终审核，中间又调用布局修复；仍失败则不导出。
- 每次模型请求内部还有网络重试，各层次数并非共享预算。
- `qualified` 表示自动状态满足条件，不是数值质量分；当前没有“达到 80 分就停止润色”的统一策略。

因此，问题是多条审核链及完成策略重新叠加，不能通过单独放宽某个提示词解决。

## 新主流程

```text
取得源字幕并保存原文 SRT
  → 冻结源单元（模型分句失败可回退源 cue）
  → 批量初译并保存候选
  → 生成成对短字幕（短句直接配对，长句联合规划）
  → 一轮综合审核：完整译意 + 双语对应 + 必要显示检查
  → 仅修复明确问题，单元共享最多三轮
  → 时间映射、本地格式检查、输出三份 SRT 和问题记录
```

初译完成后即生成可下载的保底版本。后续审核或修复成功时发布新版本；失败时保留已有版本。三份字幕写入同一产物版本目录，全部写完并验证后再更新 manifest 指向，避免原文、译文、双语来自不同轮次。

综合审核是唯一的默认质量判断。移除默认路径上重复的旧内容修订、新内容审核、独立显示审核和最终三方审核串联。保留其中对照原文、识别 ASR 噪声、核查数量/否定/频率/角色及检查逐条对应的规则，合入一次审核。

## 纠错规则

| 类别 | 例子 | 动作 |
| --- | --- | --- |
| 明确内容错误 | 漏掉一个分句、否定反转、金额错误、主体错位、凭空增加事实、跨单元重复或搬运信息 | 提供原文及译文证据，进入有限纠错 |
| 明确显示问题 | 空白条目、目标段数不匹配、内容被截断、明确词内断开、实质信息错配到另一 cue | 进入同一个纠错预算 |
| 可选质量优化 | 同义改写、措辞更优雅、可读但稍生硬、多个合法切口之间的偏好 | 默认保留；达到 80 分后停止优化 |
| 证据不足或 ASR 歧义 | 仅凭术语表猜测名称、不能证明错译的评审意见 | 保留并记录，不自动补造含义 |

80 分是模型的质量参考，不是准确率，也不能豁免明确错误。低于 80 分但只有风格建议时，不自动启动三轮润色。审校不负责通过改写原文来“修正”转录；只有上下文支持唯一明确含义时才允许译文正常解释识别噪声。

每个单元的审核结果包含：质量参考分、明确问题列表、每项问题类型和证据、可选建议、是否已完整检查。每个输入 ID 必须得到一次明确结果。缺 ID、重复 ID、无效 JSON 或请求超时表示审核未完成，不能记作已通过，也不能阻止导出。

## 三轮的严格含义

首次综合审核不算纠错。发现明确问题后，最多进行三轮：

```text
第 N 轮：只修当前有问题的单元 → 一次局部综合核验
  无明确问题：保存并结束该单元
  仍有明确问题：保存意见，进入下一轮
  第三轮仍有问题：保留可用候选，记为待复核，结束
```

- 内容纠错、源文边界、目标对齐和最终译意共用 `repair_rounds_used`；切换修复算法不获得新额度。
- 一轮至多一次修复生成和一次核验，因此最多六个纠错逻辑请求；无错误单元不进入此链。
- 不再增加模型仲裁链。核验若只有风格偏好或证据不足，不得要求继续润色。
- 已验证修复写入当前候选；核验未通过的改写单独保存，不能覆盖之前的候选。三轮都不通过时仍输出之前的初译或已确认版本，明确记录其未解决问题。
- 轮次在请求前持久化；恢复同一任务不重置。自动恢复不重复审核已完成单元。
- 网络异常最多一次自动重试，且受同一任务请求和时间预算约束；不再为每个底层请求默认再套三次。
- 修复阶段增加全片额外等待上限，初始建议 180 秒。到时保留候选输出，剩余问题标为待复核；该默认值须用指定测试服务冷跑验证后确定。它是任务结束上限，不是质量通过条件。

## 拆短与时间校准

短句两侧都在显示限制内时直接配对。长句默认复用现有联合规划能力：程序提供精确源 token 和合法宽度上界，模型一次选择源文切口与对应目标短语。避免每句先调用源文拆分，再调用目标对齐，最后再单独审核。

联合规划允许目标语言调整语序，但必须保留完整源文含义。综合审核同时比较源文、完整初译参考及最终配对；初译参考不是权威，原文始终优先。完整译文由最终目标短语顺序连接得到，避免模型同时输出两个互相冲突的译文版本。

拆短失败使用已有可用配对。没有可靠配对时，保留完整原译作为一个时间区间，允许超过显示长度目标，并记录排版警告。不能为了满足 60 显示单位而丢字、制造虚假的双语对应，或者让任务失败。单个无法安全拆开的长 URL、名称或单词也采用溢出警告。

时间映射沿用现有源文坐标：有词级时间时优先使用，否则在原 cue 区间内估算。原文和译文共享时间轴。它不构成重新听音频后的声学对齐，不新增强制对齐模型调用。

时间映射失败时局部回退到源区间；需要时合并相邻冲突 cue 并保留全部文本，以得到正时长、可解析的字幕。阅读速度、较短时长、长静音驻留和显示溢出作为质量记录，不作为禁止输出条件。真实音画同步评测单列，不能用 SRT 不重叠替代。

## 各阶段的保留策略

| 失败位置 | 最终采用的内容 | 任务结果 |
| --- | --- | --- |
| 模型分句失败或覆盖无效 | 原始 cue 或本地安全边界单元，保留全部源文 | 完成，记录分句回退 |
| 某单元初译始终没有有效结果 | 目标位置保留该单元原文 | 完成，记录未翻译 |
| 内容纠错三轮耗尽 | 之前保存的可用译文 | 完成，记录未解决错误 |
| 拆短或对应审核失败 | 已有有效配对；必要时整句输出 | 完成，记录排版待复核 |
| 审核模型不可用或响应无效 | 已保存的完整初译与布局 | 完成，记录审核未完成 |
| 时间映射不可用 | 有效源时间区间，必要时合并冲突条目 | 完成，记录时间回退 |

所有正文翻译均失败也输出字幕：原文文件正常，目标和双语中的目标部分保留原文，明确显示“已完成，全部译文待重试”。任务完成与翻译质量必须分别记录，不能伪称翻译成功。

## 速度控制

- 初译按预算合批；长句联合布局初始按 2–4 个单元合批，综合审核初始按 4–8 个单元合批，依据实际请求字节及预期输出自动缩小。
- 使用统一请求调度器，默认最多四个在途请求，避免三个阶段各自四并发造成实际十二并发和限流。
- 按批流水执行，已有候选直接进入后续阶段；不等待整片内容审校完成才启动排版。
- 上下文、术语和源文身份缓存复用。反馈只包含当前问题与必要邻句，避免累加整段历史提示。
- 初译、布局和审核分别持久化。只有时间变化时只重算时间；只有显示长度变化时只重排相关单元。
- 遇到连续认证或服务不可用错误，停止同源新审核请求，转入候选导出，避免全片每句各自耗尽重试。
- 保留问题明细供用户以后局部重试；任务完成后不自动在后台继续付费调用或无限优化。

性能验收目标：固定输入、同一模型和并发、全部冷缓存，常规无严重错误路径总请求数较当前流程减少至少 40%，总耗时减少至少 30%。这是待实测目标，不能用缓存续跑或最后一次局部两请求的耗时代替冷跑结果。

## 最小改造范围

1. `subtitle_pilot_runner.go`：统一完成策略，先保存可交付候选；收集单元问题，不再因单元质量错误提前退出整片。
2. `translation_semantic_review.go`：新主路径仅使用初译能力，关闭重复的旧修订与术语复审链。
3. `subtitle_semantic_joint.go` / `subtitle_semantic_display.go`：以联合布局为长句默认能力，拆除四轮串行规划再多级升级的默认链。
4. `subtitle_content_audit.go` / `subtitle_semantic_consistency.go`：重用审核规则，收敛为一套综合审核和局部核验，不再层层阻断导出。
5. `subtitle_manifests.go`：加入共享轮次、候选身份、审核完成与否、未解决问题及回退原因；旧检查点读入后保留原有内容，缺少新审核证据则记为未审核。
6. `translation_result.go` / `pipeline/subtitle.go`：执行成功与质量状态分开，沿用成功响应及 warnings，补充未解决内容错误、未审核及溢出计数；不能只有旧的“未翻译”计数。
7. 导出校验：硬要求文件可解析、文本不丢失、索引有效、正时长；长度、自然度及审核通过状态改为质量提示。

不重写媒体下载、ASR、生产网关或渲染体系。实现涉及 Runtime 与结果协议，按仓库 P2 要求做相关集成验证；若修改共享前端展示，补充相应定向测试与类型检查，不默认触发 Desktop 打包。

## 验收

- 85 分、无明确错误：综合审核一次，零纠错请求。
- 高分但存在明确否定反转或漏译：仍进入纠错。
- 只有同义词或风格分歧：保留候选，不进入多轮优化。
- 明确错误连续三轮不通过：三份字幕存在，任务完成，问题带单元及时间定位，轮次恰好耗尽。
- 初译或审核服务持续不可用：不会无限请求；目标位置保留可用文本或原文，正确标记质量状态。
- 拆短一直超长、模型只给标点或源文被改写：拒绝坏布局后仍能导出完整候选。
- 中途取消、请求超时、进程恢复：已输出文件保留，已完成单元不重做，预算不重置。
- 单元 A 修复失败不会删除单元 B 的已确认修复，三份产物来自同一版本。
- 对固定全片进行冷跑：统计逻辑请求、物理尝试、时间、tokens、降级与明确内容错误，比较性能目标；另以独立评审检查纠错效果。
- 本机联网验证只用用户指定的独立测试网关和 `gpt-6-luna`；离线测试使用夹具。不读取或复用生产凭据。

实现由 `runPilotTranslation` 统一进入新的交付流程，旧审核助手继续保留供历史调用和回归使用。分句失败会冻结完整覆盖源文的本地单元；请求超大时按单元隔离；无法安全拆开的超长词保留溢出，同时仍允许明确内容纠错。新增问题报告、时间回退记录和断点预算。本次未修改生产模型配置或部署线上。性能百分比目标仍需同条件旧版整片基线验证，不能由小样本结果推断。
