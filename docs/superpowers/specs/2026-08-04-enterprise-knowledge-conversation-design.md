# 企业知识对话 Dashboard 设计

## 背景与目标

现有企业知识库以文档搜索、列表和详情为核心，要求用户先找到并打开资料。新设计改为以对话为唯一主要工作流：用户直接提问，系统只基于当前身份有权访问的企业知识生成回答。

本阶段继续使用 `apps/web` 的共享静态前端，不接入 Daemon、API、向量检索或权限服务。Web 与 Desktop 使用同一组件、数据和交互。

## 产品边界

- 保留左侧“企业知识库”入口和 `#/knowledge` 路由。
- 页面不展示文档搜索、分类筛选、文档列表、文档详情、同步指标或打开文档入口。
- 知识资料只在回答底部以不可点击的知识域依据摘要出现，不暴露文档 URL。
- 静态原型提供员工和管理员视图切换，演示身份权限差异。
- 输入问题后由前端本地生成示例回答，不发起服务端请求。

## 身份与权限模型

静态数据包含两个演示身份：

- 员工视图：小林，可访问全员知识域和所属团队“客户成功”知识域。
- 管理员视图：企业管理员，可访问全部企业知识域。

每个身份包含稳定 ID、显示名、角色、部门和 `accessibleScopeIds`。每个知识域包含稳定 ID、名称、权限层级、摘要、知识条目数和示例问题。

回答匹配前必须先使用当前身份的 `accessibleScopeIds` 过滤知识域。无权限知识域不显示名称、数量或推荐问题，避免泄露受限知识的存在。身份切换时重置当前对话，防止管理员回答残留在员工视图。

## 页面结构

### 顶部

- 标题“企业知识库”和“静态示例”标识。
- 说明文案强调“直接提问，回答会自动遵循当前身份权限”。
- 右侧使用分段控件切换“员工视图 / 管理员视图”。

### 对话主区

- 主区占页面主要宽度，显示欢迎消息、推荐问题、问答记录和固定在底部的输入区。
- 推荐问题只来自当前身份可访问的知识域，点击后等同于发送该问题。
- 用户可输入任意非空问题并发送；静态回答器按关键词返回预置答案，未匹配时返回清晰的范围提示。
- 回答底部显示不可点击的依据摘要，例如“客户成功知识域 · 2 条依据”。
- 不使用文档标题作为操作控件，不提供跳转或详情展开。

### 权限侧栏

- 显示当前身份、部门和“已按权限过滤”状态。
- 仅列出当前身份可访问的知识域、权限层级和知识数量。
- 员工视图突出个人实际可问范围；管理员视图展示全企业范围汇总。

### 响应式布局

- 桌面端采用对话主区加窄权限侧栏的两栏结构。
- 窄屏下权限范围移到对话上方，输入区保持完整宽度。
- 所有固定格式控件使用稳定尺寸，发送按钮不因输入内容改变布局。

## 状态与行为

- 初始状态显示当前身份欢迎消息和推荐问题。
- 空输入不能发送。
- 发送后立即追加用户问题与静态回答，并清空输入框。
- `Enter` 发送，`Shift+Enter` 换行。
- 身份切换后清空旧消息并加载新身份欢迎消息与推荐问题。
- 页面持续标注“静态示例数据，未连接企业知识服务”。

## 数据与组件边界

- `knowledge-model.ts`：身份、知识域、回答规则、权限过滤和静态回答生成。
- `KnowledgePage.tsx`：身份状态、对话状态、发送行为和页面组合。
- `knowledge.css`：桌面两栏、移动单栏、消息、依据摘要、权限侧栏和输入区样式。
- 不修改路由协议，不新增 Desktop 专属实现，不使用 `hostBridge.kind` 分叉。

## 验证

- 模型测试覆盖员工/管理员可访问知识域不同、无权限知识不泄露、关键词回答只引用权限内知识域和兜底回答。
- 组件测试覆盖无文档列表或打开入口、角色切换、推荐问题、手动输入发送、空输入、依据摘要不可点击和身份切换清空旧对话。
- App 测试继续覆盖 `#/knowledge` 直接访问、浏览器历史恢复和侧边栏选中态。
- 运行 Web 类型检查、相关单元测试和 `git diff --check`。
- 本阶段不声称完成真实权限服务、检索服务或 Desktop 打包验证。
