# 视频翻译审核与交付优化：实施和验证

日期：2026-10-27。范围为 KrillinAI Runtime 默认视频翻译流程，以及 Daemon 对新增质量信息的透传；没有部署线上或打包 Desktop。

## 最终行为

`runPilotTranslation` 进入新的 `runSubtitleDelivery`。正常路径为冻结源单元、批量初译、长句联合拆短、一轮综合审核、必要时局部纠错、时间映射与导出。默认路径跳过旧内容修订、独立内容审核、独立显示审核和最终多遍译意审核的串联。

- 明确错译、漏译、增译、数量、否定、范围和实质对应问题进入纠错；风格建议不触发改写。80 分是实用质量参考，不是准确率，也不豁免高分中的明确错误。低分但只有风格建议时也保留。
- 每个源单元共用最多三轮纠错预算，每轮一次生成和一次核验。预算在请求前保存，恢复任务不重置。未经核验通过的修复不会覆盖已有译文。
- 有效带时间源文取得后，先保存源文保底字幕，初译产生后发布译文版本。分句、翻译、审核和拆短的模型错误都采用保留已有文本的策略；全部初译失败时，目标位置保留原文并报告未翻译。
- 超长词无法安全拆开时保留完整文本并提示溢出，明确内容错误仍可在整句保留模式纠正。异常大单元超出请求预算时单独保留，不影响其他单元初译。
- 统一限制最多四个在途模型请求，单请求超时 45 秒，默认链最多一次网络重试；审核请求持久化保留，可能更早采用已有字幕。修复阶段全任务额外等待上限为 180 秒。认证/额度错误或连续三次服务失败后停止后续同源请求。
- 正常拆短用源 token 连续范围与译文短语联合规划。模型响应缺少身份、重复身份、覆盖不全、只给标点或破坏文本时不采用；已有候选仍可输出。
- 时间映射失败时，采用源时间区间并按需要合并相邻冲突 cue。附加音频短字幕无法安全拆分或定时时，保留主字幕文本和时间。

取消、无有效源内容、损坏的持久化状态和本地读写失败仍如实报错；已发布文件保留。不能把磁盘失败伪装为模型不可用或任务完成。

## 状态与产物

执行完成与质量状态分开记录。`subtitle_quality` 新增未解决错误、超长 cue、时间回退和问题明细，原有未翻译信息继续保留。证据不足的评审意见标为待核验，风格建议不记作明确错误。问题包含源单元、局部 cue、最终字幕编号及时间区间。

三份 SRT 先写入同一个版本目录，再更新 `products/current.json`，最后发布顶层文件。另有 `subtitle_review_report.json`。重复快照复用同内容产物，避免反复生成相同文件。Daemon 会保留质量信息到产物 metadata；任务完成进度也会提示未翻译或待复核。

只改时间时复用所有模型结果；只改显示长度时复用初译，纠错预算仍不重置。恢复全部已完成任务不再调用模型；恢复未完成的修复核验会使用持久化候选及请求结果。

## 离线验证

实际完成的验证：

1. `go test ./internal/service ./internal/pipeline ./internal/types ./pkg/openai -count=1` 通过。末尾新增的超长词、超大单元隔离、附加导出和 HTTP 场景又执行了定向测试及 race 检查。
2. 最终定向/race 覆盖：75/85 分只有风格建议零修复；95 分否定错误仍纠正；漏译纠正；三轮失败保留文件且恢复不再消耗请求；审核 JSON 无效或身份无效标为待核验；证据不足不改写；断点恢复核验不多用一轮；单元间修复隔离；单元问题映射至最终时间；单词溢出不妨碍内容纠错；超大单元不拖累其他初译；超预算审核自动缩批；时间冲突合并保留文本；本地读写错误不吞掉。
3. SRT/VTT 真实 HTTP 集成覆盖三轮纠错失败和持续 503，均正常返回并输出原文、译文、双语三份字幕；SRT manifest 标记执行完成，同时质量降级。
4. FFmpeg/FFprobe 音频准备、词级时间输入、HTTP 模型协议、音频字幕导出和恢复集成通过。该音频夹具使用受控 ASR 响应，不能代表真实 ASR 准确率。
5. Daemon `creator-translation-resume.test.ts` 三项测试和 `pnpm --filter @opencreator/daemon typecheck` 通过。
6. CLI 构建和 `--help` 冒烟通过；`git diff --check` 通过。

最终 race 覆盖 `internal/service`、`internal/pipeline`、`internal/types`，并启用 FFmpeg/FFprobe 音频集成，全部通过。本次没有扩大到 Desktop 打包或线上服务重启。

## 指定测试服务冷跑

本地联网仅使用用户指定的 `http://103.121.92.95:8080/v1`、`gpt-6-luna`。测试代码要求空输出目录，明确加载独立测试配置，拒绝生产服务、备用服务和代理；没有读取生产凭据。

固定输入由既有 Notion 视频样本的开场段和食谱段组成，共两个 60 秒原始 cue。每次冷跑都重新执行分句、语境、初译、拆短与审核，不复制旧翻译/审核缓存；之后同输入恢复验证零额外请求。时间为原始粗 cue 内的位置估计，未重新听音频或进行声学强制对齐。

本次没有同模型、同输入、同并发的旧版本整片冷跑基线，因此不宣称已达到设计中的请求减少 40%、耗时减少 30%。也没有声学同步或人工盲评结论。

### 最终代码冷跑结果

使用最终代码、全新缓存：12 个源单元，生成 25 条字幕；耗时 30.49 秒，17 次逻辑请求 / 17 次物理调用，合计 25,841 tokens。纠错总计 4 轮，单元最高 3 轮。恢复相同任务的新增模型请求为 0。

最终自动质量状态 `qualified`，未翻译、未解决明确错误、未核验译文、显示溢出和时间回退均为 0。程序验证完整源文覆盖、正时长、不重叠、可解析文件及三份产物存在；对照阅读也检查了 15 个日历、Notion、条件/否定和食谱原始来源等内容。该阅读检查不构成人工盲评。

最终运行包含：分句 1 次、语境 1 次、初译 3 次、联合拆短/纠错生成 7 次、综合审核/核验 5 次。相同候选的重复核验复用持久化请求结果。没有调用旧内容修订或独立最终审核链。

开发期间另有两次相同输入的冷跑，分别为 26.04 秒 / 17 次请求 / 27 条字幕、41.14 秒 / 15 次请求 / 30 条字幕；当时仍在补充边界处理，不能视为同版本性能分布。三个运行目录均保留，最终交付以 `verified-cold-run` 的代码哈希为准。
