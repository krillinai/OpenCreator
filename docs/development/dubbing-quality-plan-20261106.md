# 视频翻译配音质量优化顺序

## 目标与边界

翻译可以单独完成，配音也可以在已有翻译字幕上启动；选择翻译加配音时使用同一条后续配音流程。源语言转录只读。配音改写只处理目标语言，最终目标语言字幕必须与实际口播一致。配音成片使用目标语言字幕，不使用双语字幕。

配音任务必须成功交付：三次改写仍无法匹配时间槽时，以变速兜底并在报告中标记明显变速。在交付成功的前提下，按意思准确、表达自然、尽量少变速来判断质量；不能为了时长改错意思。

## 当前程序流程

1. 读取已经翻译好的目标语言 SRT 和只读的源语言 SRT。
2. 保留原翻译字幕的切分，对每段生成原速 TTS，测量实际讲话时长。
3. 实测超过时间槽的单元，带源语依据改写目标句并重新生成 TTS，最多三次。首次超过 1.0 倍就进入改写；改写后不超过 1.10 倍可以接受。
4. 只有三次改写后仍超过 1.10 倍，才考虑相邻合并；通常只合并未完句。若超时的是不足 1 秒的极短后句，也允许 LLM 判断它是否是前句的动作延续。程序检查间隔和合并后目标字幕不超过 70 字，并实测合并后的 TTS；独立完整句保留原边界。
5. 仍超时则变速兜底。写入与最终口播一致的目标字幕，拼接音频并合成视频。

## 已有证据

- 2026-11-06 的完整 CLI 测试报告中，7 个配音单元超过 1.10 倍，最大 1.37 倍（2、47、55、63、91、111、113）。
- 随后只对 15 条原字幕做的隔离 CLI 音频测试，超出 1.10 倍的单元为 0，最大 1.099 倍。它不能证明完整视频已经改善。
- 隔离测试中的第 111 段“冲刺30分钟，休息枯燥”不自然；第 112–113 段对并列建议的表达也不够准确。此前只加强提示词的实验出现 1.31 倍超时，且文案未明显改善，实验改动已撤回。
- 语义合并候选范围和“先 TTS 实测、再改写”两项调整目前仍在工作区；不能把隔离测试的改善归因于其中单独一项。
- 2026-11-06 的源语失败退路修复后，用同一批配音前的 15 条目标字幕和对应源语，经当前 CLI、`gpt-6-luna` 与阿里云 TTS 重跑，任务成功，超出 1.10 倍为 0，最大 1.093 倍；原隔离测试最大 1.099 倍。两次合并分组不同（3 组与 4 组），模型输出有随机性，不能把倍率差归因于本次修复。新结果的第 91 段“会看到最常出现的”缺宾语，第 111 段“休息要无聊”不够自然，仍不满足文案质量目标。该测试只生成音频，没有验收完整视频。

## 本轮单点优化与实测

- 第 111、112 段时长分别为 2.619、2.573 秒，原 2.5 秒合并候选门槛使两段无法一起交给模型判断语义。仅把候选门槛调到 3.0 秒后，15 条隔离样本的 CLI 测试将第 111–113 段合并；超 1.10 倍为 0，最大 1.0997 倍。合并仍由 LLM 判断语义，并受相邻时间、每组数量和目标字幕 70 字上限约束。
- 用 `pkg5FkkG8jU` 已有的配音前目标字幕进行整片对照，输入 SHA-256 为 `68374cdb0903a4521c0d27b43f8914346517b34a9da098874544c88ff5f24006`。121 条源语片段从同次翻译的结构化 checkpoint 恢复，逐条确认目标文本与输入字幕一致；源语文本未改写。两次错误输入实验（一份用了配音后的目标字幕，另一份用了编号不匹配的源语字幕）不计入对照结论。
- 旧整片 CLI 报告：6 段超过 1.10 倍，最高 1.295 倍。只改 3.0 秒门槛的整片 CLI 报告：1 段超过 1.10 倍，最高 1.137 倍；58 个配音单元、40 次语义合并、47 次改写、无失败。第 115–116 段合并后仍需 1.137 倍提速，且把 `boring breaks` 说成“休息从简”，语义不够准确。因模型输出和合并分组有随机性，单次前后差不能作为稳定收益的证明。
- 两版仅调整配音改写 Prompt 的追加实验均已撤回。第一版在第 115–116 段的小样本为 1.075 倍，但口播“休息要无聊”不自然；整片虽无超 1.10 倍片段，仍出现“第二招：教中学”“第四招：计时”“睡觉，动动”等生硬或残缺表达。第二版强调自然完整短语，小样本三次改写后仍为 1.225 倍，且“休息无聊”不自然。不能用倍率达标掩盖文案退步。
- 3.0 秒门槛的整片 CLI 已生成带 AAC 音轨的 1280×720 配音视频，并通过 CLI `render-horizontal --dubbed` 烧录目标语字幕。媒体探测确认视频与音轨存在，画面抽帧确认只有中文目标字幕；尚未完成整片主观试听，不能宣称听感达标。

- 旧零合并整片报告为 121 个配音单元、7 段超过 1.10 倍、最高 1.466 倍、92 次改写。新报告为 120 个单元、仅合并第 70–71 段、0 段超过 1.10 倍、最高 1.049 倍、42 次改写、无失败。第 23、24 段分别保留。这是不同时间的一次整片对照，模型和 TTS 存在随机性，且本轮还包含讲话时长测量调整，不能把全部数值变化单独归因于合并策略。

## 2026-11-07 语义优先的改写回归

- 第 68 段源语 `Repeat.`、目标语“重复。”只有 0.527 秒时间槽。旧 Prompt 同时要求时间槽为硬上限、必须明显缩短，实测将它改成“再”并因时长达标跳过合并。Prompt 现改为先保留完整意思和自然表达；不能无损缩短时允许原样返回，由程序处理剩余时长。
- 五条字幕的 CLI 音频测试中，“重复。”保留原文，但单独配音 0.716 秒，需 1.358 倍提速。因此仅对改写后仍超过 1.10 倍的不足 1 秒后句开放前句候选，并由 LLM 判断是否是动作延续；第 67–68 段实测合并后 2.225 秒，落在 2.255 秒时间槽内，原速输出。第 70–71 段也合并并保留原文。
- 同一份 121 条配音前字幕（SHA-256 `3b4dd83ba6cfa074a60c062252f65d24581d04e5764509815eb6777f3199ba85`）经新 CLI 整片测试成功：118 个配音单元，合并 67–68、70–71、72–73，49 次改写；第 68 段保持“重复。”且原速，第 23 段保持“这叫帕金森定律。”，第 70–71 段为“有项研究，休息时玩手机的学生，”。
- 这版仍有 5 段超过 1.10 倍：8、56、77、109、111，最高第 109 段 1.487 倍；不能宣称整片自然度达标。整片 manifest 明确指定目标语言 `zh_cn`，而上一轮隔离运行的 manifest 未记录目标语言；模型和 TTS 也有随机性，倍率变化不能只归因于 Prompt。
- KrillinAI CLI `render-horizontal --dubbed` 已将最终目标语字幕烧录进视频；输出为 1280×720 H.264 + AAC，时长 287.48 秒，整片解码无报错，154 秒抽帧确认第 67–68 段字幕与最终口播文案一致。

## 按顺序处理

| 顺序 | 要解决的问题 | 最小处理与验收 | 状态 |
| --- | --- | --- | --- |
| 1 | 源语对照改写失败后，无源语回退可能改变事实 | 有源语时只接受源语对照改写；失败保留现有目标句，最多重试三次，最后变速成功。用“记住40%”被改成“占40%”的回归测试验证 | 已完成；失败路径回归测试通过，同批 15 条字幕 CLI 音频测试成功；实际触发次数尚不可从现有报告确认 |
| 2 | 完整视频是否仍有明显变速 | 用相同输入、模型、TTS，经完整 KrillinAI CLI 重跑；比较超 1.10 倍的数量、最大倍率、失败数和合并结果 | 已完成一次可比整片测试；6 段降至 1 段，最高 1.137 倍，仍未全达标 |
| 3 | 改写后语义与中文自然度 | 聚焦第 115–116 段的具体含义与自然口播，保留清单各项；下一次只验证一个最小改动，并在小样本通过后做整片回归 | 已定位残留问题；两版 Prompt 追加实验因文案质量失败而撤回 |
| 4 | 整片音频、字幕和视频交付 | 仅用 CLI 输出检查目标语字幕与口播一致；用媒体探测确认视频有有效音轨，抽听开头、中段、结尾，检查卡顿和字幕同步 | CLI 成片、音轨及中文烧录字幕已确认；整片试听待做 |

每完成一项都记录改动、对照输入、前后结果与仍未解决的问题；未通过的项继续处理，不提前推进下一项。翻译质量、声线选择、多角色和背景音不在本轮配音时长与文案优化范围内。
