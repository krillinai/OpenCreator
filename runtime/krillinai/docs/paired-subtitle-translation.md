# 双语字幕的单行分段与输入保护

YouTube 词级字幕、块级字幕、音频转录和原文 SRT 导入统一通过 `paired_translation.go` 翻译。首译每批调用一次模型，同时完成翻译、拆段和原译配对；整片初译完成后增加一次限时批量语义检查，只修必要错误。

## 输入保护

输入先按 Unicode 句子边界组织语句，保留既有英文缩写例外。整句不超过1600个UTF-8字节且满足既有预估响应预算时完整提交，避免不必要的语义接缝；必须拆分的长句仍沿用800字节片段上限，并同时检查响应预算。优先 Unicode 词边界，没有自然边界的长词、URL才退到完整字素簇边界。输入预算与最终字幕显示长度是不同约束；响应估算仍使用显示上限估算配对JSON开销。

VTT 无行内时间戳的单词行，只在上一处同词结束时间之后 10ms 内视为滚动延续并去重；跳过的延续行仍推进记录时间。后续重新出现的同词保留，不能按全片单词文本去重。

相邻前后各两句作为上下文，每句上下文最多 256 字节，仅供理解，不输出到译文。批次同时限制句数、请求字节预算和预估响应预算，避免预拆之后再次形成超大请求。请求预算包含 Prompt、JSON、上下文和纠错预留；纠错反馈也限长。响应按当前批次的预估输出加 1024 token 余量设置上限，最少 2048、最多 8192；确认截断后在原有三次输出尝试内翻倍扩大预算。未实现预算接口的翻译器保留原调用方式。预估响应预算为 6500，请求字节预算为 16000。它们是保守估算，不是针对所有模型的精确 tokenizer 或语义扩写上界。异常字素簇或无法满足预算的输入明确报错。

VTT/SRT 文本读取允许单行最多 4 MiB，之后才进入上述模型输入保护，超过读取上限则明确失败。

## 翻译与校验

原文和译文每段分别按 `max_sentence_length` 生成，任意一侧超过验收上限时增加成对字幕条数。两侧都放得下时要求保持一对；同一句内允许译文按目标语言习惯调整语序，原文只能顺序切分。完整覆盖检查只允许片段边缘的空白差异，保留段内空格及其他字符。

首译不生成或发送本地分段建议；模型依据完整输入的语法和含义选择原译配对，包括没有标点的输入。旧的建议字段及恢复反馈文案已移除。最终导出禁止在同一种语言内折行；双语字幕每条只能有原文、译文各一行。

长度采用 Unicode 字素簇字符数：中英文、数字、空格及标点每个字素簇都计1，组合字符和 Emoji 连接序列保持完整。默认生成目标为60，验收上限为65，61～65不触发长度修复，66及以上才拆分；显式配置其他长度时按该值作为硬上限，不附加百分比容差。这不是字体像素宽度，也不是 UTF-8 字节数。首译 Prompt 仍要求60，没有为了验收余量放宽生成目标。

配对翻译要求模型只返回 `segments` 配对数组，每条直接包含 `source` 和 `target`，不再重复输出整句 `target_text`。英文 Prompt 要求先理解整句、选择较短的连续意群，再将它们翻译成一份连贯译文，不能逐段重复翻译。60 字符上限下优先选择较长一侧约30–45字符的自然短语，给计数留出余量；这只是生成建议，不是额外硬上限，也不按固定词数截断。名字、数字与单位、短名词短语及动词补足语应尽量完整。语言语序不同时，允许相邻少量配对共同表达对应内容，但不能以逐词严格对齐为由输出超长段或空译文。

程序按原顺序直接拼接各段 `target` 得到内部完整译文，保留所有字符和段内空格，仅去掉整句首尾空白；有空格的目标语言须在片段边缘保留必要词间空格。这份完整译文继续用于检查点、语义审核和导出。

旧格式仍兼容：若旧结果提供 `target_text`，继续检查它与分段译文一致；纠错输入已冻结 `target_text` 时，即使模型仅输出 `segments`，也必须完整保留该译文。纯翻译兜底和语义修正仍复用完整译文字段。新格式没有第二份独立译文可供比对，不能靠结构校验证明没有漏译、增译或语义重复，这些错误依赖后续语义审核和实际抽查。

本地检查 JSON、ID、顺序、两侧片段数量、实际内容、两侧长度、单行、字素边界、原文覆盖和完整句子的目标语言特征；提供了冻结或旧格式完整译文时另检查译文覆盖。禁止实际换行、Unicode 换行控制符和会被 ASS 解释为换行的字面量转义。源文清理保留 ZWJ/ZWNJ，避免破坏 Emoji、印度文字和波斯文等内容。音频语气词过滤仅作用于无实际含义的译文填充词。

撤销模型多余切分时，必须两侧完整文本都满足长度上限，并能确认译文边界如何连接；无法确定是否为词内切分时保留原配对，避免引入或删除词间空格。

撤销多余切分后，解析器仍检查明确的中英文悬空主语，但内容完整且长度合格的结果不再仅因该软规则重新生成整组。长度修复也不为边界质量建议改动合格字幕。此规则不是完整语法分析，其他语义边界和语言仍依赖模型判断。

中文逗号、顿号差异可在本地按完整译文恢复分段，边界关闭标点归入上一段。只有删除这些标点后文字及段内空格仍一致时才允许修复，不忽略小数点、否定词等内容，不改写完整译文。新格式的完整译文由片段拼接产生，因此这一步仅能整理已有标点，无法补回模型未输出的标点。

内容完整但存在超长对时，仅将超过验收上限的原译对批量提交给独立的英文局部拆分 Prompt。每对提供完整原文和冻结译文，相邻字幕仅作为只读上下文，模型不返回整组。程序按局部ID替换成功对，未提交的合格对原样保留；下一次仅提交仍超长或修复失败的对。局部校验检查双侧覆盖、非空、单行及字素边界，不允许重新翻译；若拆后仍有长段但最长长度确实下降，可保留这些完整且更短的配对，下次仅继续拆其中的长段。遗漏、改写、重复ID、坏JSON或断网都不覆盖上一版，不再把已经完整分段的一组字幕折叠为全文一对。成功的中间结果立即保存检查点。

局部拆分与原有内容恢复共用每句请求预算和最多三次内容尝试，不额外增加重试轮数。预算用完后仍交付完整单行字幕，并报告剩余超长对。原文遗漏、空配对等导致首译内容无效时仍走原有结构纠错；最多三次配对请求后至多一次纯译兜底。始终没有有效译文时导出带 `[待翻译]` 标记的原文，恢复运行时重试该句，其他成功句不重译。

修复 Prompt 明确把当前 `Input JSON` 的完整 `text` 和已提供的 `target_text` 作为依据。上轮响应可能只是被截断的诊断节选，不能照着节选输出不完整结果；冻结译文连标点也必须保留，通用错误反馈中建议重写译文的旧文案不能覆盖这一要求。空译文或纯标点片段需要连同相邻原译区域重新分配，不能用占位内容应付校验。Prompt 改进不代表模型必然遵守所有约束，程序仍执行原有完整覆盖、双侧长度和单行检查。

每个保护后的输入句共享最多4次翻译服务调用额度，包含首次、429/5xx等接口重试、配对纠错和整句兜底；一次批量请求对其包含的每句各计一次。单次传输重试仍受 `translate_max_attempts` 的1–3次限制。额度耗尽即保留有效译文或导出明确标记的原文。这个上限不是全视频的请求上限，必要语义审核使用单独的一轮限时预算。用户取消和文件读写错误仍返回真实错误。

只有片段派生的译文，在确认原文完整覆盖之前不能冻结；源片段漏字、重复、乱序或改写时允许重新翻译。已明确提供的旧格式完整译文及此前冻结的有效译文继续兼容恢复。

有效完整译文及成功分段按句子独立原子保存；按原顺序回调提交不阻止后续成功句落盘。

恢复旧检查点时也执行当前长度验收：默认61～65字符直接复用，66及以上只将超长对送入同一局部拆分流程，合格对不变。旧检查点仅有整句译文或配对损坏时，先恢复完整原译对，再冻结译文拆分；不重新翻译。恢复拆分沿用现有并发，每句最多三次内容尝试，传输重试共用四次请求额度，不为子段追加预算。成功结果写回检查点，再次恢复无需重复拆分；失败仍保留已有完整字幕并报告超长。未译标记、无效译文及内容或语言不匹配仍走原有重新翻译路径。

## 必要语义检查

完整原句和完整译文按不超过 24000 UTF-8 字节的请求预算组织为窗口，带前后各两句上下文。每个窗口只请求一次，最多使用翻译配置中的并发数；每次 `translatePairedSentences` 调用覆盖内容的语义检查共享 30 秒预算，音频路径按转录块调用。只使用支持 context 的模型接口以保证取消及超时。未译标记句不送审，同语言任务跳过。超预算异常单句或未完成窗口保留原译，不宣称全部已经审核。

审核使用不限定语言方向的英文Prompt，只返回有原文证据的错译、漏译、增译及完整修正译文；明显损坏目标语言词语的意外连写也可修正。不逐句评分，不润色正常表达，不承担拆段。修正后的完整原文或译文超长时，冻结修正译文，复用首译配对Prompt只恢复分段；每句最多请求三次，并与审核共用30秒总预算及已有并发设置。正常的短句修正不增加切分请求。只接受当前窗口的唯一ID、逐字匹配的原译引用、本句原文中的证据和具体错误理由；继续检查内容、目标语言及单行。未超长的修正通过正常配对校验，超长修正只有在两侧长度、单行、完整覆盖及既有边界检查全部通过后才替换原有分段。恢复失败、改写冻结译文、超时或保存失败时，保留此前的完整字幕及配对，不回退为修正后的整句，不使用换行兜底。

审核请求失败、限流、截断、坏 JSON、超时及无效修正均保留已完成译文；用户取消仍终止任务。有效修正原子更新单句检查点，音频路径同时更新最终聚合检查点。模型证据并不构成语义正确性的确定保证，仍需检查实际最终字幕，不能用自评分替代质量判断。

DeepSeek V4 的 `deepseek-flash`、`deepseek-v4-flash` 和 `deepseek-v4-pro` 使用 `temperature=0.2`，减少结构和分段的随机变化，并发送 `reasoning_effort=none`，避免推理耗尽字幕 JSON 的输出预算；实测其低强度推理也可能耗尽预算。其他模型保留默认采样，不附加这些参数。接口返回 `finish_reason=length` 时明确报 `llm_translation_truncated`，不把被截断的内容当成完整译文或普通空响应。

## 时间与产物

普通原文、译文和双语 SRT 共享条数、编号和时间区间。时间定位使用去空白后的原文 rune 位置，显示单位不参与时间计算。词内切分在已知词时间内插值；仅有 cue 时间则在原 cue 区间内插值。这不是音素级对齐。

普通字幕和短字幕共用位置映射。短字幕保留完整目标片段，再独立拆分源文；YouTube 使用 `short_subtitle_max_chars`，音频使用 `MaxWordOneLine`，同时保留原文单行显示上限。无词时间的块级字幕保留普通双语兼容输出。匹配不到精确词文本时使用已有 cue 时间，避免再次整词搜索把合法词内片段判为失败。音频转录全文与词列表标点不同的兼容情况仍通过既有匹配器生成 cue，再共用 cue 位置映射。

短字幕字符参数是分组目标，`max_sentence_length` 决定生成目标和对应验收上限。短字幕最后一组只有一个空白分隔词且不超过12个字符时，允许回并前一组；无空格文字按同样的短尾规则处理。回并仍须通过长度和音频词数检查。

最终文件只报告未解决的超长内容，不插入换行、不改动字幕内容或时轴。正常输出的单语SRT每条恰好一行文本，双语SRT每条恰好两行文本，原文与译文各一行。严禁把同一种语言折成两行或更多行来满足每行长度检查。

任务完成仍优先于无限恢复：首译或检查点局部拆分预算耗尽、未译标记或时间不足导致合并等极端降级，可以保留完整的超长单行并发出明确警告，但不能把它计为满足配置的字符限制，也不会用本地字数比例切分制造双语对应。审核后恢复分段失败则保留审核前的字幕。

YouTube两条路径、音频和导入路径均使用只读的最终长度报告。内置ASS渲染不再给同一种语言插入换行，并设置`WrapStyle: 2`关闭自动折行；双语之间保留一个显式换行。竖屏单语中文沿用已有独立时间段切分。第三方播放器的视口、字体和自动折行由播放器控制。

## 验证

定向测试：

```powershell
go test ./internal/service ./internal/pipeline ./internal/subtitle_style ./pkg/util ./pkg/openai ./internal/cli ./config -count=1 -timeout=120s
```

单元测试覆盖中文、日韩、泰文、阿拉伯文、印地文、重音组合、Emoji和混合文字的字素边界与长度规则，以及两万词无标点输入、双侧长度、不安全切分、重试与取消、词内普通/短字幕时间一致性。

结构检查不等于所有语言的翻译语义均已验证；真实模型的翻译质量仍需抽查。
